Assignment Overview — LuckyTire

LuckyTire now has a normalized database, but managers need information that crosses table boundaries. You will begin with a clean instructor-normalized checkpoint and build a query that combines customer, tire, and sales information without copying those facts into one flat table.

This is a formative assignment. The goal is to learn by building, testing, and checking the database work. You do not need to submit screenshots, a PDF, or Digital Artifact Notebook evidence.

Exercise 1 — Turn Related LuckyTire Tables into Useful Information
  1. Download LuckyTire_Normalized_Formative03.accdb. Save a working copy as Formative03_LuckyTire.accdb.
  2. Open the Relationships window and identify the customer-to-sales and tire-to-sales relationships. Do not redesign or renormalize the database.
  3. Create a new query in Design View using the customer, sales, and tire tables.
  4. Include customer first/last name, invoice/date, tire model/manufacturer, quantity, and unit price fields. Use the actual field names in the starter database.
  5. Confirm that Access has joined the tables through their related key fields rather than through names or descriptive text.
  6. Sort the results by customer last name and then by invoice date.
  7. Add criteria that returns a meaningful subset of records, such as one manufacturer, one tire type, a quantity threshold, or a date range that actually exists in the data.
  8. Create a calculated field for an extended amount using quantity multiplied by unit price. Name it ExtendedAmount.
  9. Save the query as qryLuckyTireSalesAnalysis and run it.
  10. Verify at least two returned rows by checking the related source records and recalculating ExtendedAmount.
