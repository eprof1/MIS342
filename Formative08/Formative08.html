This assignment prepares you for Summative08 and continues the LuckyTire database application case.

  3. Query and verify data stored outside the Access file.

Assignment Overview — LuckyTire

LuckyTire is outgrowing a single-file database architecture. Access can remain the employee-facing application while selected data reside on a MariaDB/MySQL server. In this assignment you will use the course-approved ODBC connection and evaluate what changes when the data are stored on another computer.

Security: use only the instructor-provided ODBC/DSN or connection procedure. Never paste an ODBC password, database password, API key, or connection secret into Hermes.

This is a formative assignment. The goal is to learn by building, testing, and checking the database work. You do not need to submit screenshots, a PDF, or Digital Artifact Notebook evidence.

Exercise 1 — Use Access as a Front End to a LuckyTire Database Server
  1. Download LuckyTire_Normalized_Formative08.accdb. Save a working copy as Formative08_LuckyTire.accdb.
  2. Confirm that you are on the required campus network/VPN and can reach the instructor-designated MariaDB/MySQL host.
  3. In Access, use External Data > New Data Source > From Other Sources > ODBC Database and choose Link to the data source by creating a linked table.
  4. Use the approved 64-bit ODBC configuration and link the instructor-designated LuckyTire table, such as a locations, service, customer, tire, or sensor-related table.
  5. Open the linked table and identify the linked-table indicator in the Navigation Pane.
  6. Open the table in Design View or inspect its properties. Note that Access can display metadata while the actual records remain on the server.
  7. Create a simple query against the linked table that filters, sorts, or summarizes a useful subset. Save it as qryLinkedLuckyTire.
  8. If a matching local table or data set is available, compare at least one row count, value, or result between local and server-backed data.
  9. Use phpMyAdmin or the instructor-approved server-side viewer, when available, to confirm that at least one value returned through Access exists in the MariaDB table.
  10. Use Hermes to explain one ODBC/client-server issue or error message if needed. Provide only non-secret error text and object names.
  11. Save and close the Access database.
