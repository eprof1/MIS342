Project Purpose and Learning Outcomes

Project03 is the capstone Access application project. You are given the relational data foundation; your primary responsibility is to turn that structure into a coherent, tested business application.

Primary CLO: CLO 12 — Develop, document, demonstrate, and evaluate a complete business database application.

Supporting CLOs: CLOs 3, 4, 5, 6, 7, 8, and 11.

After completing this project, you will be able to:

  1. Inspect and evaluate an existing relational structure through at least 3NF.
  2. Create purposeful queries that retrieve, calculate, summarize, parameterize, or appropriately modify data.
  3. Create forms/subforms and navigation that support business workflows.
  4. Create reports designed for specific operational or managerial audiences.
  5. Automate one appropriate workflow with a macro/event and one introductory VBA module/procedure.
  6. Develop and execute a systematic test plan and explain the evidence that the application works.
Individual accountability: you may collaborate on planning, troubleshooting, and peer review, but every student submits an individual final database and must be able to demonstrate and explain it.
Starting Point and Design Boundary
  • Use the instructor-provided Project03 Access database containing the required business tables and relationships.
  • Do not create a completely new schema just to increase the number of tables.
  • Use Project03 Database Structure Review Guide to inspect keys, relationships, data types, referential integrity, and normalization.
  • You may correct a material structural problem, but document the problem, reason, change, and test.
  • ODBC is not required for Project03. The project must remain demonstrable even if external servers are unavailable.

Phase 1 — Structure Review and Application Plan
  1. Create a working copy of the instructor-provided database and preserve an untouched original.
  2. Use DatabaseDesign.htm to inspect keys, data types, relationships, referential integrity, and normalization.
  3. Identify the main business processes represented by the data.
  4. Create an object plan: list the purpose of each proposed query, form, report, macro/event, and VBA procedure.
  5. Define at least five business questions/tasks the application must support.
  6. Create a preliminary test plan before building the final objects.

Phase 2 — Build the Application Layer
  1. Create the required purposeful queries and verify representative results.
  2. Create the required forms, including a main form/subform and a data-entry/maintenance form.
  3. Create a startup/navigation form that allows a user to reach the main application functions without depending on the Navigation Pane.
  4. Create three audience-focused reports, including a grouped/summary management report.
  5. Create one macro/event workflow.
  6. Create one standard VBA module/procedure with a known business rule that can be tested.
  7. Use consistent naming such as qry..., frm..., rpt..., mcr.../macro names, and mod... for a standard module.

Phase 3 — Test, Evaluate, and Demonstrate
  1. Execute the planned normal, boundary/unusual, invalid/error, and known-result tests.
  2. Correct defects and rerun the failed tests.
  3. Verify at least one query result against source records, one report total against its source query, one form edit against the underlying table, and one VBA/macro result against a known expected outcome.
  4. Document any known limitation that remains and explain why it is acceptable or how it should be addressed later.
  5. Have another student perform a short usability test if class time permits; incorporate a useful improvement when justified.
  6. Prepare a concise demonstration that shows the business workflow rather than clicking randomly through objects.
