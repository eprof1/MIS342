Assignment Purpose and Learning Outcomes

Formative10 introduced database automation and showed that code can compile while still implementing the wrong business rule. Summative10 asks you to assemble a more application-like LuckyTire interface and independently test both macro/event behavior and VBA business logic.

After completing this assignment, you will be able to:

  1. Create a simple navigation/menu interface for a database application.
  2. Use a macro or command-button event to automate a repeatable task.
  3. Import, read, test, and troubleshoot VBA in a standard module.
  4. Use a known expected result to identify a logic defect.
  5. Evaluate AI-assisted code recommendations by compiling and testing them in Access.

Primary course learning-outcome alignment: CLOs 7 and 8, with supporting evidence for CLOs 11 and 12.

Questions 1 through 6 require concise answers of no more than 500 characters. The Final Assignment Reflection allows a longer response.

Exercise 3 — Debug and Verify VBA Business Logic
  1. Import modLuckyTireServiceFee_Broken.bas as a standard VBA module.
  2. Compile the VBA project. Notice that successful compilation does not prove the business calculation is correct.
  3. Run the known test: LaborAmount = 200, PartsAmount = 300, ShopFeeRate = 0.05. The correct total is $525.
  4. Read the function yourself and predict why the original result is wrong.
  5. Use Hermes optionally, or Direct Mode, to review the .bas source and propose the smallest correction.
  6. Correct the function so it returns base labor + parts plus the percentage shop fee.
  7. Recompile and rerun the $525 test, then test a second known input of your choice.
  8. Save the corrected module/database.
