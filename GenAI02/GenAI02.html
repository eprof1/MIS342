Recommended Workstation Layout and File Formats

Use the multiple monitors

Use the classroom workstation displays instead of stacking every application on one screen. Keep the important windows visible so you can compare instructions, agent actions, files, and verification evidence as you work.

  • Monitor 1: Keep Hermes Desktop open with the active MIS342 profile visible.
  • Monitor 2: Keep a browser open to OpenRouter and the published assignment in separate tabs. During API-key creation, use the OpenRouter tab, then navigate away from the key page before capturing any evidence.
  • Laptop display or third monitor: Keep Notepad++ open with the required course file. Use File Explorer or OneNote beside it when organizing workspace files or evidence.

Use Windows Snap (Windows + Left Arrow or Right Arrow) when two windows must share a display. Before taking a screenshot, close or hide API-key, billing, authentication, and private-information pages.

Use Notepad++ for Markdown and plain-text files

Use Markdown (.md) for student-created artifacts that benefit from headings, lists, checklists, or tables. Use plain text (.txt) for simple source excerpts, rules, prompts, or configuration notes where formatting adds no value. Hermes can read both formats.

  1. Open File Explorer and turn on View > Show > File name extensions.
  2. Open the starter file in Notepad++.
  3. For a Markdown file, select Language > M > Markdown so headings and lists are easier to read.
  4. Use File > Save As, select All types (*.*), and enter the exact required filename ending in .md or .txt.
  5. Use UTF-8 encoding and confirm the file did not become filename.md.txt.
  6. Do not use Microsoft Word to create these files because it can add formatting and change the file type.

If Notepad++ is not installed, use the official Notepad++ installer or contact the instructor before continuing. Windows Notepad may be used only as a temporary fallback.

Close and reopen PowerShell 7.6 after installation, then run:

Step 3 — Create the separate MIS362 profile before adding any course credential

A profile separates Hermes configuration, API keys, memory, sessions, skills, and other course-specific state. Students taking more than one course must not mix course work in the same profile.

  1. In Hermes Desktop, open the profile selector or Profiles page.
  2. If a profile named MIS342 already exists, select it and skip to Step 4. Do not create MIS342-2 or another duplicate.
  3. Select New profile.
  4. For the profile name enter exactly MIS342. Use lowercase letters.
  5. For Clone from, select default. Keep default as a clean general profile rather than a course workspace.
  6. Leave the optional SOUL.md box blank for now.
  7. Select Create profile, then set or switch to MIS342 as the active profile.

Verify in PowerShell 7.6:

hermes profile list
hermes profile use MIS342
hermes profile show MIS342

The list must mark MIS342 as active. From this point forward, perform MIS362 provider, model, memory, skill, and tool configuration only while MIS342 is active.

Step 4 — Create and install the OpenRouter credential inside the active MIS342 profile

  1. Create or sign in to your OpenRouter account.
  2. Open the OpenRouter API Keys page.
  3. Create a normal model-access API key named exactly MIS362_API_Key01. Do not create a management-only key.
  4. Use a reasonable spending or credit limit when that option is available.
  5. Copy the key and paste it directly into Hermes Desktop under Settings > Providers > API keys > OpenRouter while the active profile is MIS342.
  6. Do not save the key in OneDrive, Notepad, OneNote, D2L, source code, GitHub, email, Teams, screenshots, prompts, or an assignment workspace. If the key is lost, revoke it and create a new one.
  7. Select the instructor-designated OpenRouter model.
  8. Start a new Hermes session in the MIS342 profile and send: Reply with exactly: MIS362 Hermes connection verified.

Step 5 — Final verification

  • Hermes Desktop opens.
  • The active profile is MIS342.

Hermes Tools and Safety Boundaries

Enabled AI tools for this assignment

  • Chat, model selection, provider configuration, session creation, and viewing tool activity.
  • The instructor-designated OpenRouter model.

Prohibited AI tools and actions

  • Hermes file writing, terminal execution, browser automation, messaging, account connections, scheduled tasks, purchases, record changes, and autonomous external actions.
  • Displaying or storing the API key in OneNote, D2L, screenshots, source code, GitHub, email, Teams, or ordinary project files.

Approval rule: Keep normal Hermes approval prompts enabled. Review every proposed file write, command, browser action, or configuration change before approving it.
