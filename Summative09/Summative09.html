Assignment Purpose and Learning Outcomes

Formative09 introduced advanced relationships and the danger of action queries. Summative09 requires you to create, preview, run, and verify controlled data-changing queries while protecting the original/shared data.

After completing this assignment, you will be able to:

  1. Analyze many-to-many and one-to-one relationships.
  2. Use a junction table to explain many-to-many data.
  3. Preview affected rows before running action queries.
  4. Create and verify make-table, append, update, or delete queries on a local working table.
  5. Create indexes and evaluate the risk of action queries against shared linked data.

Primary course learning-outcome alignment: CLOs 3, 4, and 8, with supporting evidence for CLOs 9 and 11.

Questions 1 through 6 require concise answers of no more than 500 characters. The Final Assignment Reflection allows a longer response.

Exercise 2 — Create a Safe Local Action-Query Target
  1. Use an existing invoice-total query (such as qryInvoiceTotal) as the source for a make-table query that selects a limited tire subset, such as TireType = Performance or Truck.
  2. Before converting/running it as an action query, run the equivalent SELECT criteria and record the expected row count.
  3. Create the local table tblSpecialTire with the make-table query.
  4. Create an append query for a second explicitly limited subset and preview the same criteria with SELECT first.
  5. Run the append only after the previewed rows match your intended scope.
  6. Verify the resulting row count and representative values in tblSpecialTire.

Exercise 3 — Update/Delete and Index Safely
  1. Create a SELECT query identifying a small, explicit subset of tblSpecialTire to update. Verify the rows first.
  2. Convert the copy to an update query and make a harmless instructional change to a local descriptive value; run and verify it.
  3. Create a SELECT query identifying a small subset that could be deleted. Record the expected count, then convert a copy to a delete query and run it only on tblSpecialTire.
  4. Open tblSpecialTire and verify the update/delete results.
  5. Add indexes to two fields useful for lookup/join/filtering while allowing duplicates when the business data can repeat.
  6. Do not run any action query against ODBC-linked/shared tables.
