Assignment Overview — LuckyTire

LuckyTire now uses more complex relationships and data-changing queries. These features are powerful, but they can also damage many records quickly. This assignment emphasizes prediction, backup, limited scope, and verification before accepting a change.

This is a formative assignment. The goal is to learn by building, testing, and checking the database work. You do not need to submit screenshots, a PDF, or Digital Artifact Notebook evidence.

Exercise 1 — Change Data Safely and Explain the Relationship Model
  1. Download LuckyTire_Normalized_Formative09.accdb. Save two copies: Formative09_LuckyTire_Backup.accdb and Formative09_LuckyTire.accdb. Work only in the latter.
  2. Open the Relationships window. Locate the employee/invoice many-to-many relationship implemented with the assignment/junction table when present. Identify the two one-to-many relationships that create the many-to-many association.
  3. Locate a one-to-one relationship such as customer-to-credit-card when present and identify why the related key must remain unique.
  4. Create a make-table query or another instructor-approved action query that copies a limited subset of records into a new local working table. Run it only in your local working database.
  5. Before running a second action query, first create a SELECT query using the same criteria so you can count and inspect the records that would be changed.
  6. Open SQL View and copy the candidate SQL into Hermes. Ask Hermes to predict what it changes and identify a potential danger. Tell Hermes this is Microsoft Access SQL.
  7. Run the limited action query only after your SELECT preview and Hermes review agree with your intended scope.
  8. Open the affected table and verify the changed row count/values.
  9. If your database contains linked tables, do not run the action query against shared linked data. Use the local working table only.
  10. Save and close the database; retain the untouched backup.
